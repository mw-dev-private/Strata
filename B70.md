# Strata on an Intel Arc Pro B70 (SYCL) — notes, patches and measurements

*mw-dev-private, October 2026.* Work done with OpenCode (Claude) as the coding assistant; the direction, the
hypotheses and the many dead ends are mine.

This branch of [Strata](https://github.com/Niko1221/Strata) carries what I changed and measured while running
**Qwen3.8-Flash-Next (GSQ-RCO IQ3_S, 131072-token context)** every day on an **Intel Arc Pro B70 32 GB**. Everything
is **opt-in by environment variable** unless written otherwise; without the variables the engine behaves as upstream.
One exception, called out below: the SYCL command-graph recording (`STRATA_NATIVE_GRAPH`) is on unless set to `0`.

**Intel Arc only.** Everything on this branch is the Intel engine (`sycl/`), built with `-DSTRATA_ENABLE_SYCL=ON`;
upstream's own CMake then configures no other backend and stops with a `FATAL_ERROR` if CUDA or HIP is switched on
together with it. No CUDA, ROCm, Metal/Mac, multi-GPU or Windows path is built, run or measured here, and no file of
theirs is modified.

CMake options that matter here:

| option | default | meaning |
| --- | --- | --- |
| `STRATA_ENABLE_SYCL` (upstream's gate) | `OFF` | builds the Intel engine from `sycl/` and **nothing else** — the project returns right after `add_subdirectory(sycl)`. Setting `STRATA_ENABLE_CUDA` or `STRATA_ENABLE_HIP` alongside it is a `FATAL_ERROR`, so an Intel build here can never quietly contain CUDA or HIP. Every measurement on this page uses `ON` |
| `STRATA_INTEL_GDN` | `ON` | build Intel's GDN delta-rule kernel (needs the cutlass-sycl sources). Chosen only at run time by `STRATA_GDN_INTEL`; with it off the built kernel is inert. |
| `STRATA_CUTLASS_SYCL_DIR` | from `-D` or `$STRATA_CUTLASS_SYCL_DIR` | where the cutlass-sycl tree is (`include/`, `tools/util/include/`, `applications/`). CMake checks `include/cute/tensor.hpp` and prints `Intel GDN delta kernel: OFF` if it is missing. |

## Every variable this branch adds or uses

**This branch's own.** "Default" is what the code does when the variable is unset.

| variable | default | production | what it does | measured here |
| --- | --- | --- | --- | --- |
| `STRATA_NATIVE_GRAPH` | **on**, `=0` off | 1 | SYCL command graphs are recorded with native device-side recording instead of host replay. | carried over from the production snapshot; no isolated measurement on this branch |
| `STRATA_TAIL_SKIP_MAX_CACHED` | `90.0` | unset | Upper bound (share of cached experts) above which tail skipping is switched off again: near-full caches gain nothing and risk more. | gate only, no timing |
| `STRATA_PREFILL_CPU_SHARE_MAX` | `3072`, floor `1024` | unset | With the CPU prefill share armed, chunks below this size are staged after their routing so the host pool can take its share. | not measured in isolation on this card |
| `STRATA_Q6_PLANES_INPLACE` | off, needs exactly `1` | 1 | Repacks the IQ3/Q6 output head into aligned planes **inside its own device allocation**, keeping the existing wide arithmetic and reduction order; no second weight copy. MTP raw-subset gathers rebuild original rows when needed. | **+1.32 %** weighted decode (58.9251 → 59.7015 tok/s, four frozen requests per arm, 512 tokens each, 13,422 slots); prefill unchanged |
| `STRATA_Q6_PACKED_WIDE` | off, needs exactly `1` | implied by the row above | The packed wide path on its own, without the in-place repack. | not measured alone |
| `STRATA_Q6_WIDE_COOP` | off | 1 | Wide Q6_K decode kernel that loads the weight bytes cooperatively into local memory (a Q6_K block is 210 bytes at 2-byte alignment, so a lane's own 16-byte load is split by the hardware). Same lane/k ownership and the same arithmetic order, so **every output bit is the same**. | parity proven; timing carried in the branch total, not isolated |
| `STRATA_MMVQ_Q6K_FAST` | off | 1 | Q6_K decode unpack as one packed SWAR subtraction instead of the ported `sub_sat` on `char4`; codes are 0..63, so `q − 32` never saturates — **bit-identical**. | parity executable against the wide kernel |
| `STRATA_MMVQ_K4_FAST` | off | 1 | The same unpack idea for the Q4_K/Q5_K decode rows. | two parity executables (Q4_K, Q5_K) |
| `STRATA_SYCL_QSA_CHUNK_DOWN` | off | 1 | Master switch for the chunked-down QSA attention path. Hard-gated: `n_head 24`, `n_head_kv 2`, `page_size 4`, cache capacity 2,051 (T1–T6 and T32) or 32,768 (T1–T6), **and the device must be Battlemage**. On any other card it never dispatches. | dispatch is checked by `qsa2582_check` (expected vs. actual, per phase, with masked and non-resident pages, shuffled physical layout, tail chunks) |
| `STRATA_SYCL_QSA_PREFILL` | **on**, `=0` off | unset | Phase sub-switch (prompt side) for the row above. | — |
| `STRATA_SYCL_QSA_DECODE` | **on**, `=0` off | unset | Phase sub-switch (decode side) for the row above. | — |
| `STRATA_SYCL_QSA_VALUE8_K8_VEC` | **on**, `=0` off | 1 | Vectorised 8×value / 8×key loads in the QSA decode attention kernel. | — |
| `STRATA_PREFILL_REFILL_ASYNC` | off, needs exactly `1` | 1 | Batches the copies that restore expert-cache slots lent to prefill, with up to 16 owned pinned host buffers (≤64 MiB; 40.62 MiB on IQ3_S) keeping the DMA sources alive until the batch drains. See [sycl/README_prefill_refill.md](sycl/README_prefill_refill.md). | prefill 21.1104 → 20.4182 s, refill phase **2.3619 → 1.6855 s** (three alternating 32K/640 pairs); decode unchanged. An earlier version with a redundant host-to-host copy: **no gain**, replaced |
| `STRATA_PREFILL_REFILL_VERIFY` | off | 0 | Reads every restored slot back and compares every weight byte to its owned source; a mismatch fails the request. Correctness runs only — the readback is not free. | **542 slots at 2K and 6,296 slots at 32K all bitwise equal** |
| `STRATA_GDN_INTEL` | off | **0** | Intel's delta-rule (GDN) stage for prompt processing, instead of Strata's own. Needs `STRATA_INTEL_GDN=ON` at build time and reserves ~63.9 KB per padded token of scratch (≈1.05 GB for a 16,384-token chunk, ≈2,064 MiB at the `auto:32768` ceiling) **before** the expert cache grabs the space — without the reservation the first chunk dies with `UR_RESULT_ERROR_OUT_OF_RESOURCES`. | parity against a reference build is exact; **no speed win measured on the engine, so it stays off** → [sycl/README_gdn.md](sycl/README_gdn.md) |
| `STRATA_GDN_INTEL_OUTWR` | off | — | `=1` is the A/B fallback to the old separate output-write. The default reads the kernel's FP16 output directly in the out-norm kernel: the FP32 copy carried no extra bits, so `y16` is **bit-identical**. | md5 equality guard |
| `STRATA_GDN_WS_MEMSET` | off | — | `=1` restores zeroing the A/w/u workspaces. The kernel audit shows every cell is written before it is read (the only real requirement is zeroing when no initial state is passed, which the engine never does); this is the fallback if that audit is ever wrong. | audit + poison test below |
| `STRATA_GDN_WS_POISON` | off | — | Proof mode: fills A/w/u with **FP16 NaN** instead of zeros. If the kernel ever read an unwritten cell, NaN would reach the output and parity would fail. Freshly allocated memory can contain accidental zeros, which is why the ordinary parity run does not prove this. | `intel_gdn_parity --poison`: passes → the zero fill is provably unnecessary |
| `STRATA_GDN_REF` | `ref/gdn_ref_T256.bin` | — | Reference output for the GDN parity harness (`--ref`). | — |
| `STRATA_TAIL_KL_LOGITS` | unset | — | Diagnostics: writes the full logits of the emitted rows on a fixed continuation (needs `--spec-follow`). This is how the KL numbers below were produced. | — |
| `STRATA_DBG_CPU_GATE` | unset | — | Diagnostics: prints, per layer, the measured cost of the CPU share and whether the next layers take it. | — |
| `STRATA_Q6P_SELFTEST` | off (`1` or `2`) | 0 | Diagnostics: bitwise parity of the repacked head against the GGUF-layout kernels for 1–8 columns, plus paired timings. Verification only — it distorts throughput. | passed in the combined build |

## What did not help (measured, so you don't have to)

| idea | result |
| --- | --- |
| Porting the whole production flag set from the 0.1.44 line onto v0.1.45 as a **speed** measure | matched 32K-prompt + 256-token A/B, three alternating pairs: decode **64.17 → 63.73 tok/s** (−0.7 %), prefill **18,883.0 → 19,005.7 ms** (+0.6 %). No gain established; the value of the port is that it is bit-identical on a newer upstream, not that it is faster |
| asynchronous loan refill with an intermediate host-to-host copy | no gain; replaced by reading the GGUF slices straight into the owned pinned buffers |
| turning the async refill on and measuring the whole server cold-vs-warm | cold prefill −2.77 %, incremental prefill **+3.81 %** (a loss), aggregate prefill −1.95 %, decode unchanged |
| `STRATA_GDN_INTEL=1` on the engine | kernel output is exact and the scratch reservation works, but no engine-level win was measured, and it costs ~1 GB of device memory at a 16K chunk — off in production |
| counting the readback of `STRATA_PREFILL_REFILL_VERIFY` as performance | it is a correctness cost, never a speed number |
| ahead-of-time device code (`-DSTRATA_SYCL_AOT=bmg-g31`) | token ids identical, speed equal within noise (decode 64.2 / 64.7 AOT vs 63.5 / 65.4 JIT; 511-token pass 1,067 / 1,071 vs 1,078 / 1,085 ms; 16K prompt 896 vs 896 tok/s). Only a ~3 % faster start — production stays on JIT |
| `STRATA_PF_XMX=1` / `=2` (grouped FP16 XMX GEMM for prefill experts) | ignored in JIT builds on Battlemage, so measured in the AOT build: `=1` 511-token pass 1,207 ms (−13 %), 16K 838 tok/s (−6 %); `=2` fused 1,064 ms (±0), 880 tok/s (−1.7 %). Token ids identical — off |
| `STRATA_PROMPT_ATTN_XMX=1` (XMX-armed prefill attention) | 16K prompt 686 / 695 tok/s vs 889 / 887 (**−22 %**), −26 % at tile 32 |
| `STRATA_VERIFY_EAGER=1` (bypass native-graph replay) | decode 57.3 vs 63.8 tok/s (**−10 %**) with identical token ids. Replay is the default; "eager" in the source is a debug switch, not a mode worth testing again |
| BF16 / W4A16 weights for the dense projections | correctness passed, token ids identical, and the bench justified **neither** a production change nor a blanket rejection: the chain was not resident, so allocation and transfer were inside the times. Not carried; the open step is one prepared, resident measurement with transfer timed separately |
| an isolated llama.cpp-style XMX gate/up adapter (32×16 tiles, K-splits, pre-packed VNNI activations) | candidate took 1.66–2.74× the existing path's time across all 21 shapes, and the safe adapter to our decoders needs 40 KiB of local memory per work group where the original needs 12 KiB, which caps concurrent work groups. Accuracy was fine (NRMSE ≤ 2.5e-7, no NaN/Inf). Dropped; no engine integration |

The isolated XMX adapter row here, and the fused-expert-kernel and int8-dot rows in the front page's
"Tried, measured, thrown away", were produced on the **Arc Pro B60 test card**; several XMX switches were first
screened there. They are reported as statements about the architecture — no B70 speed number comes from that card.

## How each change is checked

1. **Kernel parity, per change:** `mmvq_q6k_fast_parity`, `mmvq_q5k_fast_parity`, `mmvq_q4k_fast_parity` (FAST unpack
   against the wide kernel), `qsa2582_check` (dispatch expectations per phase and shape, with masked/non-resident
   pages and tail chunks), `intel_gdn_parity` (`--selftest`, `--ref`, `--poison`, `--expect`).
2. **Whole-model output:** three prompt fixtures (104 / 1,500 / 32,000 input ids), 64 forced continuation positions
   each, **248,320 logits per position bit-identical** to the previous production binary, **KL zero**; `CPU_SHARE=0`
   used on both sides to isolate arithmetic placement; both builds at 13,423 cache slots.
3. **Server side:** 346 Python tests over the server, the prefix encoder and the compatibility settings.
4. **Weights, not just outputs:** `STRATA_PREFILL_REFILL_VERIFY=1` compares every restored cache slot byte by byte.

## Not tested

Multi-GPU, non-GGUF expert sources, long stability runs, vision throughput, Windows, and any **published** number on
a GPU that is not an Arc Pro B70. The box does have a second Arc (an Arc Pro B60, `8086:e211`) that I use as a test
card, and some kernel experiments ran there; that makes it a measurement bench, not a supported target — nothing in
this branch is tuned for it and no speed table on this fork was measured on it. The CUDA, HIP and Metal engines are
not built on this branch at all (see the CMake gate above), so nothing here says anything about them — read them as
Intel Arc Pro B70 statements or not at all.
The `--long` bench was run once per side (n = 3 per test, medians quoted), and the engine I measure is the JIT build,
not an AOT one.
